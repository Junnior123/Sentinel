# Sentinel — 앱 사용과 로컬 테스트

외부 운영을 시작하려면 **[지금 할 일만 따라하기](DEPLOY-EASY.md)**부터 읽으세요. 아래 첫 절은 같은 PC에서 하는 개발 테스트입니다.

**아래 localhost 절차는 개발 테스트용입니다. 외부 사람에게 localhost 주소를 보내면 연결되지 않습니다.**
Cloudflare 웹·DB와 GitHub 로그인 연결을 완료했습니다. Windows 11 새 설치·타 PC 제출 검증은 남아 있습니다.
기존 Watchblock의 새 이름은 Sentinel입니다. 예전 초대 파일과 소스 폴더 이름은 호환성을 위해 유지합니다.

## 1. 지금 직접 해볼 일

1. **`Sentinel-0.5.1-Setup-x64.exe`를 실행 → 설치 위치 확인 → 설치**를 누릅니다. 관리자 권한은 필요하지 않습니다. 바탕화면 바로가기는 선택 사항입니다.
2. 설치 완료 화면에서 실행하거나 시작 메뉴의 **Sentinel**을 엽니다. .NET을 따로 설치할 필요는 없습니다. 설치 없이 사용하려면 ZIP을 전체 압축 해제하고 `Sentinel.exe`를 실행해도 됩니다.
3. 로컬 서버가 켜져 있다면 같은 PC의 브라우저에서 `http://localhost:8787/dev/login`을 엽니다.
4. **검사 만들기**를 누르고 닉네임과 사유를 입력합니다. 넓은 검사를 하려면 **전체 파일·드라이브 검사**를 선택합니다.
5. **코드 발급 → 초대 링크 복사**를 누릅니다. 코드는 15분 이내에 한 번만 연결할 수 있습니다.
6. 앱에 링크를 붙여넣고 **연결하고 계속**을 누릅니다.
7. 처음에는 작은 테스트 폴더를 추가하고 기본 C 드라이브 항목을 제거해서 확인하세요. 다음 검사에서 **권장 C 드라이브**를 사용하면 됩니다.
8. 전송 대상과 검사 위치를 읽고 동의한 뒤 **검사 시작**을 누릅니다.
9. 완료 후 **누락·제한**을 먼저 읽고, **보고서 저장**으로 전체 결과를 보관합니다. 검토 후 **보고서 제출**을 누릅니다.
10. 브라우저 검사 목록에서 해당 결과를 엽니다. 탐지 근거와 실행 흔적을 구분해서 검토하고 의견을 저장합니다.

로컬 서버가 꺼져 있으면, 소스 폴더에서 아래 명령으로 시작합니다. Node.js 24와 pnpm이 필요합니다. 명령을 실행한 창은 켜둡니다.

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm local
```

개발용 자동 로그인은 이 로컬 서버에만 있습니다. 외부 운영용 Worker에는 포함되지 않습니다.

## 2. C 드라이브 검사 범위

설치 기본 위치는 `%LOCALAPPDATA%\Programs\Sentinel`입니다. 업데이트는 앱과 검사를 종료한 뒤 새 Setup을 실행하세요. 같은 위치에 덮어 설치하며 기존 서버 설정은 보존합니다. 삭제는 Windows **설정 → 앱 → 설치된 앱 → Sentinel → 제거**에서 진행합니다. 직접 저장한 보고서·서버 설정과 별도 로컬 하드웨어 비교 기준은 자동 삭제하지 않습니다. 설치 패키지의 코드 서명은 아직 적용하지 않았습니다.

| 포함하는 위치·항목 | 처리 |
| --- | --- |
| 사용자 폴더, Downloads, Desktop, AppData (Temp 제외) | 숨김 파일을 포함해 열거 |
| Program Files, Program Files (x86), ProgramData 및 C의 다른 폴더 | 읽을 수 있는 파일의 목록·해시 검사 |
| JAR·ZIP·EXE·DLL·SYS·지원 스크립트 | 지원하는 내부 구조와 검증된 규칙 검사 |
| 문서·그림 등 기타 형식 | 파일명·크기·해시만 기록, 내용의 의미는 분석하지 않음 |

권장 설정은 Windows 업데이트 저장소, DriverStore·시스템 드라이버, Windows Temp·사용자별 AppData/Local/Temp, 기본 Steam steamapps·Epic Games·Riot Games 설치 위치, NVIDIA·AMD 설치 임시 폴더, 가상 메모리 파일을 제외합니다. 휴지통은 일반 파일 열거에서 제외하고 선택한 휴지통 검사로 처리합니다. 정확한 경로는 앱의 **제외 위치 보기**에서 확인합니다. 별도 위치에 설치한 게임은 계속 검사될 수 있습니다. **제외 위치에 치트가 없다고 보증하지 않습니다.** 제외 체크를 해제하면 이 경로도 시도합니다. 임의의 `cache`라는 이름이나 Sodium·AppleSkin 같은 파일명으로 검사에서 제외하지 않습니다.

권한 부족, 링크, 클라우드 전용 파일, 손상 파일은 누락으로 기록합니다. 파일당 256MB, 250,000파일, 100,000폴더 한도가 있습니다. 한도에 도달했다면 `부분 완료`이며, 남은 위치는 새 검사에서 폴더별로 나누세요. 전체 드라이브가 반드시 모두 검사된다는 의미가 아닙니다.

관리자 권한 체크는 **실행 흔적 보조 검사**에 적용됩니다. 모든 파일 읽기 권한을 자동으로 얻는 기능은 아닙니다. 다른 사용자 프로필은 접근이 거부될 수 있습니다.

## 3. 진행률을 읽는 방법

- **파일 목록 준비:** 발견한 개수만 표시합니다. 아직 전체 개수를 모르므로 백분율을 만들지 않습니다.
- **파일 검사:** 처리 개수 ÷ 발견한 전체 개수로 백분율을 표시합니다. 읽기 실패·크기 제한도 처리한 항목에 포함됩니다.
- **예상 남은 시간:** 초기 측정 이후 파일당 평균 처리 시간으로 계산합니다. 대형 JAR, 디스크 상태 때문에 변동하며 파일 검사 단계만의 추정입니다.
- 파일 단계가 100%가 된 후 **서명·실행 흔적·시스템 변경 검사**가 이어질 수 있습니다.
- 검사 도중 새로 생긴 파일은 목록에 없을 수 있으므로 새 검사에서 확인합니다.

## 4. 외부 플레이어와 실제 운영하기

실제 운영은 [Cloudflare 배포 안내](DEPLOY.md)를 따라 진행합니다. 새 `pnpm setup:production` 명령이 HTTPS 주소·D1 ID·설치자 정보를 받아 실서버 설정을 따로 만듭니다. Cloudflare 계정 가입부터 GitHub 로그인 연결, Setup 다운로드 게시, 다른 PC 검증까지 순서대로 설명되어 있습니다. 로컬 `/dev/login`은 공개 서버의 로그인 수단이 아닙니다.

## 5. 상세 보고서를 공개 링크로 공유하기

1. 제출 완료된 결과를 엽니다.
2. **공개 보고서 공유**를 펼칩니다.
3. **탐지 근거 / 전체 파일 목록 / 실행·삭제 흔적 / 검사 누락·범위** 중 공개할 항목을 체크합니다. 아무것도 고르지 않으면 요약만 공유합니다.
4. 공개 범위에 동의한 뒤 기간(기본 **7일**)을 고르고 **공유 링크 만들기**를 누릅니다.
5. 나타난 링크를 복사합니다. 로그인하지 않아도 선택한 상세 항목과 파일명·해시를 볼 수 있습니다.
6. **공유 중지**로 즉시 철회합니다. 다시 만들면 이전 링크는 무효가 됩니다.

요약과 선택한 상세 항목을 공개합니다. 파일 목록은 100개씩 조회하며 해시·분석 상태, 탐지 근거와 기록 시각을 펼쳐 볼 수 있습니다. 닉네임·사유·검토 의견·인증 정보는 공개하지 않으며 개인 경로는 마스킹합니다. 상대 파일명 자체는 공개되므로 공유 전에 확인하세요. 실제 공유 만료일은 생성 후 표시됩니다. 보고서 보관 만료가 먼저 오면 선택한 기간보다 짧아집니다. 보고서 삭제·보관 만료 시 링크도 사용할 수 없습니다. 기본적으로 어떤 보고서도 자동 공개하지 않습니다. 로컬 링크는 같은 PC에서만 시험할 수 있습니다.

## 6. 실사용 전 알아둘 현재 한계

- 파일명을 바꿔도 해시와 내부 특징으로 검사합니다. Meteor 계열의 오토 크리스탈·활 조준 보조 구조 규칙을 포함하지만 모든 에임 어시스트·모든 치트에 대한 탐지율을 검증한 것은 아닙니다.
- 난독화로 내부 특징을 바꾸거나 메모리에서만 작동하는 프로그램은 놓칠 수 있습니다. 파일 발견과 실제 게임 사용은 다른 사실입니다.
- 넓은 검사에서 보고서가 10MB를 넘으면 일부만 전송합니다. 전체 결과는 로컬 저장하고, 운영 시 범위를 나누어 다시 검사하세요.
- SSD/HDD 전체 드라이브의 소요 시간·탐지율, 실제 Windows 11 배포, 공개 OAuth와 Cloudflare 환경은 별도 실사용 시험이 필요합니다.
- 하드웨어 변경은 비교 기준·설정 흔적입니다. 첫 실행에서 과거 스푸핑을 확정할 수 없고, 정상 업데이트도 변경을 만들 수 있습니다.
