# Sentinel 0.3.1 검사 성능

검사 범위, 전체 파일 SHA-256, 내부 클래스 검사, 원본 보존, 취소와 압축 한도를 유지했습니다. 정상 프로그램 이름으로 제외하거나 이전 실행의 해시를 재사용하지 않습니다.

## 변경

- 파일 파서와 서명 검사를 각각 최대 2개 작업으로 제한해 동시 처리합니다. 작업별 파서 상태를 분리하고, 완료한 파일만 합칩니다.
- PE 문자열 규칙이 없으면 실행 파일을 다시 통째로 읽어 문자열로 만들지 않습니다. 해시와 PE 헤더 검사는 유지하며 문자열 규칙이 추가되면 자동으로 다시 검사합니다.
- 제외 경로를 한 번 정규화해 해시 집합으로 조회합니다. 디렉터리 열거에서 이미 받은 속성도 재사용합니다.
- 파일마다 UI로 돌아오던 서명 반복문을 작업 스레드로 옮기고 서명 단계에도 처리 개수를 표시합니다.

## 같은 표본에서 측정

실제 .NET DLL 100개와 검증된 배포 표본 11개, 파일시스템 캐시가 있는 상태에서 예열 후 3회 측정했습니다. **파일 단계만** 측정했으며, 서명·실행 흔적·네트워크 전송은 포함하지 않습니다.

| 중앙값 | 0.3.0 | 0.3.1 |
| --- | ---: | ---: |
| 파일 검사 시간 | 508.12ms | 384.03ms |
| 관리 힙 메모리 할당량 | 약 458.4MB | 약 50.7MB |
| 처리 파일 / 치트 일치 / 검토 | 111 / 11 / 0 | 111 / 11 / 0 |

이 표본의 시간은 약 24%, 메모리 **할당량**은 약 89% 감소했습니다. 할당량은 최고 메모리 사용량과 다릅니다. 전체 C 드라이브, HDD와 캐시 없는 파일에서는 다른 결과가 나올 수 있습니다. 전체 파일을 해시하므로 저장된 파일이 많으면 여전히 시간이 필요합니다.

재현 명령: `dotnet run --project desktop/Watchblock.Bench -c Release -- . current`. 먼저 회귀 표본을 준비해야 합니다. 원시 기록은 개발 작업 폴더의 `artifacts/benchmark-before.json`과 `benchmark-after.json`입니다.

## 회귀 검증

- 순차·동시 검사 파일 목록, 크기, 해시, 형식, 상태, 탐지 결과 일치.
- PE 문자열 규칙을 넣은 경우 이름이 바뀐 파일에서도 문자열 검사 유지.
- 총 C# 88개 검증, API·계약 14개 테스트 통과.
- 실제 앱의 검사·제출, 웹의 조밀한 결과 목록·근거 열기와 공개 링크 생성·철회 확인.

앱의 기본 창은 1200×800이며 최대화는 선택할 수 있습니다. 공개 요약은 기본 7일, 선택 1·3·7일입니다. 서버의 기존 보고서 보관 만료일은 연장하지 않습니다.
